# Local-use and federation security review

Independent security-agent review of source and existing tests. No credentials were read, model tasks launched, or external messages sent. The reviewer found no confirmed authority escalation or credential-read escape; this was not a container-escape penetration test. Workspace tests passed at review time.

| Priority | Finding | Required change |
| --- | --- | --- |
| High | Workers bind a writable host workspace. CPU, memory and process limits do not prevent exhausting the laptop's disk. | Give each run hard-bounded storage, then export bounded regular-file artifacts. A directory-size polling check is not a hard quota. |
| Medium | A server crash interrupts bookkeeping without reconciling or stopping the old worker containers. Retrying can overlap an old credential-mounted worker. | Label workers by node/run/attempt, reconcile before dispatch, and add cancellation/shutdown cleanup. |
| Before third-party UI tools | Tool windows currently share the operator origin. Repository-built assets are trusted, but a third-party window would inherit browser authority. | Isolate external windows on a separate origin with a narrow capability bridge. |

Evidence: writable bind and resource limits in `src/worker.rs::container_command`; deadline cleanup in `execute`; startup interruption handling in `src/storage.rs::load`; same-origin frame and script policies in `src/runtime.rs` and `src/web_assets.rs`. Disk exhaustion and server-crash survival were not exercised experimentally.

Positive boundaries: loopback binding; operator authentication; numeric Discord identities and recipient bindings; dispatch-time authorization; run-derived room scope; bounded, symlink-resistant mailbox reads; source snapshots only for explicitly authorized improvement runs. Neither peer federation nor untrusted UI installation is ready for release. Address storage bounds and worker supervision before broader unattended use.
