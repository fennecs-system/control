From source

Build the regular release.

Start with macOS, Nix with flakes enabled, Git, and a running Linux Docker-compatible engine. Worker image builds need a Linux Nix builder. These commands use Apple Silicon; on Intel, select x86_64-linux for the worker image.

1. Build

git clone https://github.com/fennecs-system/control.git
cd control
nix develop
cd web
trunk build --release --locked
cd ..
cargo build --release --locked --bin control
./target/release/control config init

2. Configure your node

Private configuration lives in ~/.config/control/, outside the checkout. Initialization preserves existing files. Set CONTROL_CONFIG_DIR to an absolute path for a different directory. Chats and outputs live separately in ~/.local/state/control/.

nix build .#packages.aarch64-linux.worker-image -o result-worker
docker load -i result-worker
umask 077
docker image inspect control-worker:nix --format '{{.Id}}' > "$HOME/.config/control/worker-image-id"

Use your own Codex login with file-based credential storage. The worker mounts its private auth.json read-only; keep credentials out of source, images and chat. See the authentication instructions for the login command and supported paths.

3. Start

./target/release/control doctor
./target/release/control serve

# In another terminal:
./target/release/control open
# Or use terminal chat:
./target/release/control tui

Ask for a small project, then a follow-up about its files. Open Artifacts to view the result. Restarting Control uses the same state.

Discord is optional. Its activated bridge reads a private discord.env in the configuration directory; numeric ID bindings determine access. User accounts can run tasks without architect or website operator privileges. Follow the Discord setup before enabling it.

Where things stand

Codex is the connected backend today. Claude, API and self-hosted adapters, live federation, and artifact editing are still on the roadmap. Earlier active containers block new dispatch after a restart; automatic cleanup and cancellation remain pending. Snapshot publication is bounded, but live workspaces do not yet have a hard disk quota.

Use model access according to your provider’s terms. Sharing a personal subscription with others may violate those terms and risk suspension.
